# 抽奖活动 · 先说能不能做

## ⚠️ 现阶段的判断：谨慎，且必须走官方组件

**账号目前是高危状态**，策略是「极保守、慢慢洗白」。抽奖是平台重点监控的营销行为，在高危期做，风险 > 收益。

**我的建议**（可以跟用户争论，但要先说清楚）：

1. 账号健康度恢复之前，**优先做互动型内容（图鉴自测）代替抽奖** —— 一样能激活评论区，零合规风险。
2. 真要做，**必须用小红书官方抽奖组件**（发布时选「抽奖」功能），不要在文案里自己写规则。
3. 一个月最多 1 次。

如果用户坚持要做，按下面的合规做法执行，并在交付时把风险说明写进 `content.md`。

## 合规红线

**绝对不能写进正文 / 图片**：
```
❌ 评论区扣 1 / 评论区扣「抽奖」
❌ 评论区告诉我 X，我抽 N 个送
❌ 私信我领取 / 加我 V 领
❌ 关注 + 点赞 + 收藏 三连才有资格
❌ 转发到朋友圈截图给我
❌ 第一个留言的送 X
```
这些全部触发「引导评论 / 引导私信 / 引导跳转 / 诱导互动」redline。**post-004 当年写过「评论区留言…第一个留言的送你解读」，那是旧写法，现在废止。**

**可以做的**：
```
✅ 用小红书官方抽奖组件（平台自己管规则、自己开奖）
✅ 正文只陈述：「这次送 N 份 XX，用的是平台抽奖」
✅ 奖品是产品内的东西（积分 / 一份深度报告 / 会员天数）
✅ 开奖后单独发一条公示（合规 + 建立信任）
```

## 奖品设计

| 奖品 | 好处 | 注意 |
|---|---|---|
| **积分 / 体验额度** ★ 首选 | 直接拉产品使用，不用寄东西 | 兑现流程要通 —— 见下面「兑现踩过的坑」 |
| 一份深度报告 | 高感知价值，成本低 | 生成要时间，说清楚多久给 |
| 会员天数 | 拉留存 | |
| 实体周边 | 互动最高 | 要地址 = 收集个人信息，高危期别碰 |

### ⚠️ 兑现踩过的坑

产品有过一个**系统级 bug：Stripe webhook 从未触发积分 grant，100+ 付费用户没拿到积分**。

做任何送积分的活动之前：**先跟工程侧确认发放链路是通的**，并且准备好手动补发的路径。中奖了拿不到东西，比不做活动伤害大得多。

## 分镜（3 张标准版）

活动帖要短。长了像广告。

| # | 内容 |
|---|---|
| 1 | 封面：送什么 + 一个视觉钩（灵体 / 报告截图）。大字铺满 |
| 2 | 产品图：奖品长什么样（真实报告截图，干净局部） |
| 3 | 说明：为什么送 + 平台抽奖入口提示。一句话 |

**2 张版**：封面 + 说明。更安全。

模板 → `templates/editorial-gradient/` 或 `card-light/`

## 文案模板

```
上个月有人问我，这个报告到底长什么样。

与其解释，不如直接送几份。

这次拿出 {N} 份{奖品}，用平台的抽奖功能开，我不经手。
{一句话说明奖品是什么、能看到什么}

（图 2 是其中一页，我自己那份）
```

**要点**：
- 不喊「福利来了」「限时」「速抢」
- 「我不经手」建立信任，也是合规声明
- 保持第一人称、保持手记口吻
- 收尾不要 CTA

## 活动节点

跟节令走，见 `tuwen-seasonal`：新年 / 立春 / 开工日 / 生日月 / 产品周年。

## 交付时必须附的风险说明

写进 `content.md`：

```markdown
## 活动合规说明
- 抽奖形式：小红书官方抽奖组件（非文案自组织）
- 奖品：{什么}，发放链路：{谁发、怎么发、多久}
- 已确认发放链路可用：是 / 否
- 账号风险评估：账号当前 {状态}，本月已发活动帖 {N} 篇
- 开奖后需要发公示：是
```
