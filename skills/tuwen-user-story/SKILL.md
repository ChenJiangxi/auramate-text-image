# 用户故事 · 最缺的那块证据

叙事随笔证明「做产品的人是真诚的」，数据背书证明「技术是硬的」，只有用户故事能证明「**别人也在用，而且有用**」。

C 端玄学赛道信任门槛极高。这类内容一个月 1–2 篇，性价比最高。

## ⚠️ 隐私 · 先过这一关

发别人的话之前：

```
□ 拿到明确授权（用户同意公开这段话 / 这张截图）
□ 昵称、头像、ID 全部打码或替换
□ 具体到能定位个人的信息删掉（生日全日期、城市 + 职业 + 年龄的组合、公司名）
□ 聊天截图里的其他内容裁掉
□ 涉及健康、感情、家庭的敏感细节，改写成概括，不引原话
□ 不确定能不能发 → 不发，或改写成「有人跟我说」的转述
```

**没有授权就用转述**。转述一样有力，风险为零：

> 有个用户跟我说，她因为这个报告里的一句话，把辞职的决定推迟了三个月。

## 三种可做的类型

### 1. 正面反馈（最常见）

一条真实的用户反馈 → 展开讲这个功能为什么这么设计。

**关键**：不要停在「用户夸我们」，要落到「她说的这件事，正好是我们当初想解决的」。否则就是软文。

### 2. 差评改进记 ★ 最有价值

「用户说这个功能不准，我去查了代码，发现是……」

这类帖的效果远好于正面反馈：
- 显示你在听
- 显示产品在改
- 天然工程叙事，零红线
- 承认问题反而建立信任

分镜：封面（有人说这个不准）/ 我去查了什么 / 发现的问题（可放代码或日志截图，**注意别露出用户数据**）/ 改成了什么 / 落点

### 3. 用户来信体

一封（授权的）长反馈 + 我的回信。文学感强，适合模板 A 的编辑风。

## 分镜（5 张标准版）

| # | 页型 | 内容 |
|---|---|---|
| 1 | 封面 | 用户那句话的浓缩，加引号。「她说这句话的时候我愣了一下」 |
| 2 | 正文 | 完整的（脱敏后的）反馈内容 |
| 3 | 正文 | 我的反应 / 我去查了什么 |
| 4 | 产品图 | 相关功能的真实截图 |
| 5 | 正文 | 落点：这件事说明什么、我们改了什么 |

模板 → `templates/editorial-gradient/`

## ⚠️ 截图红线（这类最容易踩）

用户反馈截图 = 满屏文字 = **「图里带信息」的高危区**。

- ❌ 直接贴一整屏聊天记录 / 长评论
- ✅ 用**排版重写**那句话（模板 A 的正文页，大字排出来），不贴原始截图
- ✅ 真要贴截图，只截**一两句**，其余留白，并且打码

这是「图里不能带信息」这条铁律最容易被忘掉的场景。

## 素材来源

- 小红书评论区 / 私信（要授权）
- 产品内的灵签反馈（用户每晚点「准不准」，这是产品自带的反馈闭环）
- 客服 / 社群
- 应用商店评价

## 红线

```
□ 授权拿到了
□ 昵称头像 ID 全脱敏
□ 反馈里的违禁词换掉（用户自己会说「算得真准」→ 改写成「跟我对得上」）
□ 不贴大段文字截图，用排版重写
□ 不做「用户见证式」营销结构（「XX 用了三天就……」）
□ 不承诺效果（「她照做后运势好转」= 直接违禁）
□ 差评改进记里的日志 / 代码截图不含用户数据
```

**最后一条特别提醒**：用户原话里经常带「准」「灵验」这类词，转述时**必须改写**，不能因为「这是用户说的」就原样发 —— 平台不区分谁说的。
