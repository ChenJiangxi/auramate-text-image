# 功能上新 · 把广告写成手记

## 先说频率

**一个月最多 2 篇。** 纯上新帖在小红书天然是广告，发多了直接压账号权重。

配比参考：每发 1 篇功能上新，前后要有 3–4 篇叙事随笔 / 知识解析托着。

## 核心转化：从「上线公告」到「我做了个东西」

| ❌ 上线公告 | ✅ 工程师手记 |
|---|---|
| 全新功能重磅上线 | 我最近把它的 X 模块做完了 |
| 三大亮点 | 我想解决的是这么一件事 |
| 立即体验 | 我自己用了一个月 |
| 支持 A/B/C | 它现在能做到这个（配真截图） |

**绝不用的词**：重磅 / 全球首个 / 上新 / 限时 / 全新升级 / 立即体验 / 赋能 / 打造。

## 分镜（5 张标准版）

| # | 页型 | 内容 |
|---|---|---|
| 1 | 封面 | 钩子 = **用户的痛，不是功能名**。「我一直想知道自己出生到底几点」 |
| 2 | 正文 | 场景痛点。具体到一个真实的困扰 |
| 3 | 产品图 | 主视图 —— 信息最密集那张（折线 / 雷达 / 地图 / 全景） |
| 4 | 产品图 | 细节视图 —— 点开某一项之后 |
| 5 | 正文 | 我为什么做它 + 落点。不推销 |

**6 张版**：中间插一张「做的过程」（工程细节 / 翻过的车），人味儿更足。

模板 → `templates/editorial-gradient/`

## 产品截图（这类帖的命门）

上新帖的可信度全靠截图。规则：

1. **信息量要大**。一张顶一屏 —— 12 个月的折线 > 一个评分环。用户原话：「信息量太少」。
2. **要完整、要铺满**。不放截断的半张，不留大片留白。
3. **要干净**。功能页主体常是干支矩阵（满屏红词），**先扒干净局部再判断**，别一看就整张弃掉：
   - 折线 / K 线趋势图 ★
   - 雷达图 / pentagon
   - 评分环、月份标签、热力图、地图
4. **裁紧到内容边缘**，去黑边 void。
5. **一整套用同一份数据**。不同报告的数字混在一起会打架。

取图优先级和裁图方法 → `auramate-tuwen/references/04-assets.md`

## 标题 vs kicker：分工别搞反

这是这类帖最常见的失手。两个位置的职责完全不同：

| 位置 | 职责 | 写法 |
|---|---|---|
| **大标题** | 钩情绪 | 写**痛点 / 被说中的瞬间**，不写功能操作名。「在哪个城市我会过得松一点」 |
| **kicker（顶栏小标签）** | 给读者定位 | 写**具体是什么**。「灵伴 AI · 新功能 · 旺运地图」 |
| **foot（底栏）** | 数据标注 | 「越红越舒展」。是标注，不是广告语 |

```
❌ 标题「旺运地图上线了」+ kicker「做了点东西」   ← 两个都反了
✅ 标题「在哪个城市我会过得松一点」+ kicker「新功能 · 旺运地图」
```

### 别把情绪主体也一起删掉

「大标题不写功能名」只是在说：别把「PDF 导出 / 旺运地图 / 收藏筛选」这种**功能操作名**当钩子。
如果情绪成立的原因正是用户和产品之间的关系，`灵伴 AI` 就是句子的主语，不是该删的广告词。

```
❌ 有些话，我终于存下来了
   ← 虽然短，但把「是谁说中了我」这个最有辨识度的情绪主体删了

✅ 那些被灵伴 AI 说中的话，我终于存下来了
   ← 写的是被陪伴、被说中的瞬间，不是在报功能参数
```

**用户已经亲自改过标题时，原句优先级最高。** 除非用户明确让重写，否则只调标点、空格和封面断行，
不再替换核心名词，不把具体关系改成「有些话 / 那个瞬间」这类泛化表达。

同一句在不同位置可以这样分工：

| 位置 | 文案 |
|---|---|
| 发布标题 | `功能更新：那些被灵伴 AI 说中的话，我终于存下来了` |
| 封面 kicker | `灵伴 AI · 功能更新 · 对话导出` |
| 封面大标题 | `那些被灵伴 AI 说中的话，我终于存下来了` |

> **真实返工（2026-08-10）**：第一版标题被用户连续评价「我觉得标题很不吸引人」「标题真的很不吸引人」。
> 用户最后亲自给出：「功能更新：那些被灵伴AI说中的话，我终于存下来了」。问题不只是字不够抓人，
> 而是改写时把 `灵伴 AI` 这个被说中的对象关系稀释掉了。

**「不营销」不等于「说话含糊」。** kicker 写「做了点东西」不会显得谦虚，只会显得没内容 ——
那个位置本来就是用来说清楚的。详见 `auramate-tuwen/references/03-copywriting.md` 第三节。

## 封面灵体 vs 内页产品图：各自证明一件事

陪伴、对话、记忆、收藏这类功能，封面先承接情绪主体：用一张**真实产品生成、构图好看的灵体**；
具体怎么操作，则放在内页用真实 UI 截图证明。不要让一个后台弹窗承担封面的情绪，也不要全篇只有灵体、
看不见功能证据。

以「对话导出 PDF」为例：

- 封面：真实灵体 + 情绪标题；
- 内页：日期勾选 / 收藏筛选 / PDF 成品，至少两张真实产品图；
- UI 截图若只负责演示步骤，就不要为了“有产品图”硬塞进封面。

## 产品图页的 label

顶栏 kicker 和底栏 foot **不要自我标注**：

```
❌ 真实产品截图 / 产品 demo / 官方截图 / 功能演示
✅ kicker：旺运地图 · 02   /   灵伴先看了我的底子
✅ foot：「灵伴 AI · 人生 K 线」+「红涨吉 · 绿跌凶」
```

自我标注「真实」在小红书上显假、显广告，反而降低可信度。

## 教程型变体

如果这篇的目的是「教已有用户怎么用」而不是拉新：

- 收藏率会远高于赞，这是好事
- 分镜改成：封面（这个报告怎么读）/ 步骤 ×3–4（每张一个产品截图 + 一句说明）/ 落点
- 可以更工具化一点，但**仍然不能出现「教你算」「学会看盘」**
- 标题：「这份报告我看了三遍才看懂，整理了一下」
