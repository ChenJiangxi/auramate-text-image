# 02 · 视觉系统

## 通用规格（所有模板）

- **尺寸 1242 × 1660**（3:4 portrait，小红书标准）。日签 / 手机截图流可用 1080×1920。
- **一种字体**。靠 weight 拉层级，不靠换字体。
- **字号最多 4 档**。别每个元素一个字号。
- **不加字间空格**，自然断行。
- **全部左对齐**（封面标题可居中，但正文和盒子一律左对齐）。
- 底部固定品牌签 `AURAMATE` / `auramate.net` 或 `灵伴 AI · AURAMATE`。

> 这几条是 2026-07-01 用户连发反馈定下的。原话：「那么多种字体…尽量保持一种」「绕口 / 不整齐」。

## 模板 A · 渐变编辑风 ★ 定版主力

**用在**：叙事随笔、知识解析、功能上新、节令 —— 也就是绝大多数。

2026-07-01 用户大转向定下的模板（之前是深色风），已跑通 6 篇以上。**默认就用这套，别自己发明。**

### 色 / 字规格

```css
/* v2 (2026-08-10)：底色加深 + 两角柔光 + 纸感颗粒。
   v1 的渐变太寡淡，中间发灰，看着像渲染出来的带状色块而不是设计。 */
背景  radial-gradient(120% 90% at 10% 2%,  rgba(132,98,178,0.20) 0%, transparent 54%),
      radial-gradient(95% 72% at 98% 102%, rgba(228,152,92,0.18) 0%, transparent 56%),
      linear-gradient(108deg,#dccfef 0%,#e7d9e9 34%,#f0e2d7 64%,#f8dcc4 100%)
颗粒  feTurbulence baseFrequency 0.85 / opacity 0.42 / mix-blend-mode multiply
      （SVG data URI 内联在模板里，自包含，不依赖外部图）
正文字 #302c2e      标题 #1a1420      紫 accent .em #6b3f8f
红棕 accent（英文词）#8a5a52   kicker #8d7d9e   footer #9e8a99
字体  正文 'Noto Serif SC'（宋体，文学感）
      kicker / footer 'Noto Sans SC'
边距  88px（v1 是 96，收紧一点给内容让位）
```

> accent 紫从 v1 的 `#7a5a8a` 换成 `#6b3f8f`。旧的太灰，读者看不出是刻意强调。
> 想更醒目可以用 `#7b3fb0`，但会偏亮、跟水彩插画的柔调有点冲。

### 字号（只有这四档）

| 元素 | 字号 | 说明 |
|---|---|---|
| 封面大标题 | **150 / 132 / 106**（按每行字数，见下） | 标题是封面主角，手动 `<br/>` 断行别拆词 |
| 内页 head | **52** | 产品图页的说明标题 |
| 正文 | **44** | 所有 slide 统一，line-height 1.9 |
| kicker / footer | **26** | 灰紫小字，算 meta 不算正文 |

> 「正文统一」和「封面标题大」不矛盾：body 统一 44，cover title 单独放大。

**封面标题字号按每行字数选**（1242 画布、88 边距，可用宽度 1066）：

| 每行字数 | 字号 | 说明 |
|---|---|---|
| ≤ 6 字 | **150** | 短钩子标题 |
| 7–8 字 | **132** | 默认 |
| 9–10 字 | **106** | 长标题 |

超了会自动折行、把你的手动 `<br/>` 断行冲掉。实测 148px 配 8 字就爆了 ——「低谷期最大的坑，」会断成两行。改字号前先数字数。

### 三种页型

1. **封面页** — kicker + 分隔线 + 大标题（`flex:1` 垂直居中，占上半）+ 底部插图横带 + footer。

   **标题是主角，插图是配角。** 插图 = 底部一条固定 **400px**（画面 24%）的横带，
   `margin:0 -88px` 出血到左右边缘、不留圆角，只在上沿加一道浅阴影分层。

   踩过的两个坑：
   - v1 插图 `max-width:540px` 只占一半宽度，两侧和上方大白 → 犯了自己定的「不留白」。
   - v2 矫枉过正，插图 `flex:1` 铺满 → 图喧宾夺主。用户原话「标题最重要，配图不能占大头」。

   竖构图插画裁成横带会切掉下方主体，用 `object-position:center 76%` 把背影/主体拉回画面。
   **换插图要重调这个百分比**，渲完肉眼确认主体在带子里。

   **信息图（图表 / 产品截图）不能裁**，按形状分两种放法：

   - **横构图**（benchmark 图、宽截图）→ 留出血横带 + `object-fit:contain` + 配贴近图底色的背景
   - **近方形**（雷达图、五边形）→ **别塞进出血横带**，contain 会左右留一大片底色。
     改成**居中圆角卡**：去掉 `margin:0 -88px`，`.illo` 用 flex 居中，
     `img` 用 `height:100%;width:auto;border-radius:24px` + 四周阴影。
     图自己就是那张卡，浅渐变露在两边 —— 看着是设计，不是没填满。
     横带高度给到 **520–560px**，卡才够大。
2. **正文页** — kicker + 2–3 段正文 + footer。**每张写满字**（280–340 字，跑 `check-fill.js` 量），
   别一段一张、别大片留白。
   内容是「N 件并列的事」时用 `<ol class="list">` 编号列表（紫色编号块 + 加粗要点独占一行 +
   下面解释）；是一条推导链就保持段落 —— 编号会把前后的推导关系切成并列。见 `03-copywriting.md` 第七节。
3. **产品图页** — kicker + head(52) + 产品截图卡 + footer

4. **成对对比页** — kicker + head(52) + 左右两栏（各一张图 + 名字 + 一句话）+ footer。
   知识解析型的核心页型：靠对比讲清楚区别，比一次列十条好读。
   **左右必须各用各的真实素材**，不能同一张图充两个角色。

   ⚠️ **图文混排页：先定行数，再倒推栏宽。别让文字栏跟着 `flex:1` 自由伸缩。**

   2026-08-12 十天干图鉴 v1 被打回，原话「这张图的字怎么那么少？我给你的参考图不是这样的」。
   文案跟参考图**一字不差** —— 差的是栏宽：我的文字栏 `flex:1` 撑到 640px、正文 42px，
   同样 27–34 字只排出 **2 行**；参考图栏宽约 480，同样的字排 **3 行**。
   行数少两行，整页立刻显空，读者感知就是「字少」。

   做法：定死「每段 3 行」→ 每行 12 字左右 → 栏宽 = 12 × 字号。
   本例 `.txt{width:560px;flex:none}` + 正文 46px，20 个段落全部 3 行，整篇节奏一致。
   插画那栏拿 `flex:1` 吃掉剩下的宽度、`justify-content:center`（人物细长时两侧留白对称，
   比 `flex-end` 把人贴边、中间空一大条好看）。

产品截图卡样式：
```css
border-radius:26px; border:1px solid rgba(90,70,95,0.26);
box-shadow:0 22px 54px rgba(60,40,70,0.26);
/* portrait 手机截图 → .shot{height:100%} 居中（默认） */
/* landscape / 近方图 → .shot{width:100%;height:auto} + img 同 */
```

⚠️ 容器一定要 `flex:1; min-height:0`。少了 `min-height:0`，portrait 截图按 `width:100%`
会撑到 1900px 高，把上面的标题挤出画面 —— 深色压字风踩过这个坑。

⚠️ **横构图截图放进竖版 slide，图和 foot 之间必然空一块。** `shot.html` 里有个可选的
`.note` 解读段（34px）专门用来撑满 —— 顺便还多讲了一句内容。竖构图铺满高度时把 `.note` 删掉。

模板文件 → `templates/editorial-gradient/{cover,body,shot,pair}.html`

### `id="slot"` 约定 —— 要出动图的容器

**素材本来是动的就别出静帧。** 灵体形态、产品动效这类，静帧丢掉了内容里最有意思的部分。
小红书图文支持 GIF，长按会播。

给要动的那个容器加 `id="slot"`，然后：

```bash
node tools/slide-gif.js <slide.html> <录屏.mov> <out.gif> [秒数=4]
```

工具会读出 slot 的位置和圆角、生成圆角蒙版、把录屏合成进去，**只有槽位在动**。
体积超预算会自动降档并打印退到了哪一档。完整说明见 `tuwen-archetype-quiz`。

## 封面规则（所有模板通用）

1. **字要大、铺满画面。** 不要小字挤在顶部三分之一、下面一大片空。用户 2026-06-15 原话：「字大一点，占满整个篇幅」。
2. 3 行排版（每行 4–6 字）约 180px 是不出血的上限；要再大就改 2 行。
3. 标题 ≤ 18 字最好；用户给出的高辨识度情绪句可以更长。先把「功能更新 / 功能名」移到 kicker，
   再用 3 行断句和 106px 档解决，**不要为了凑字数删掉情绪主体**。
4. 关键词用 accent 色 `<span class="em">` 标出来，1–2 个就够。
5. 封面必须有情绪钩子或反预期，不要抽象口号。
6. **标题的主语要在画面里。** 标题写「灵伴 AI 说中的话 / 陪我熬过的夜」，封面就用真实产品灵体；
   标题写某张图表的反常识结论，封面才用那张完整信息图。不要拿导出弹窗替代陪伴感，也不要放一张
   “反正挺好看”的无关图。

### 陪伴类功能的封面分工

对话、回忆、收藏、长期陪伴这类功能，推荐一套固定分工：

- **封面**：真实产品生成的灵体，负责品牌辨识和情绪；允许作为氛围图用 `object-fit:cover`，
  但必须调 `object-position`，保证灵体主体完整、好看；
- **内页**：真实产品 UI，负责证明功能怎么用、结果长什么样；
- **不要二选一**：只有灵体会像情绪海报，只有 UI 会像操作说明书。

> **真实返工（2026-08-10）**：对话导出 PDF 帖，用户先要求「配上产品图」，又要求
> 「配上好看的灵体」。两句话并不冲突：产品图属于步骤和结果页，灵体属于封面；前者证明功能，
> 后者承接「那些被灵伴 AI 说中的话」这个标题。
